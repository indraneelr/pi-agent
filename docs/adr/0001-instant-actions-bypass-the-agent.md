# Instant actions bypass the agent; the agent only generates content

Agent turns cost 40–144s, so routing every UI action through the LLM would make the product unusable — especially on mobile. We split user actions into two kinds: **instant actions** (select, deselect, remove, slot-into-day, download) mutate the server's canonical trip state deterministically with no LLM turn and update the UI optimistically, while **generate actions** (more options, images, reviews, activity research, itinerary draft, budget) invoke the agent. The trade-off is that the agent is no longer in the loop on every choice, so it cannot react conversationally to a selection (e.g. "great pick, Naxos pairs well with Milos") unless the user explicitly asks — we accept that to keep tapping instant.
