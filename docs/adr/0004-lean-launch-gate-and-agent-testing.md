# Lean launch gate and agent testing strategy

We want to ship an MVP fast, so we explicitly do **not** gate launch on the full E01–E15 LLM-judge eval harness (slow, flaky, high-maintenance, and its p50≤8s latency target is already unrealistic given 40–144s turns). That comprehensive automated quality suite is **deferred to beta**. The v1 launch gate is: **(1)** deterministic-shell tests green (instant actions, state, SSE events, failover/timeout logic, image-URL validation, per-user API isolation); **(2)** integration tests that run our components end-to-end with the three expensive/flaky boundaries — **model, search, image** — stubbed via injectable seams (`createTravelSession` already takes `model: Model<any>` and `searchProvider`, and the session facade exposes `subscribe(event)` so the SSE event stream is observable without a browser), while everything else runs real in-process; **(3)** a thin golden-path smoke; and **(4)** a written manual-dogfood checklist run against the Greece/Japan/Portugal matrix before each release.

Model determinism uses a **hybrid**: a **scripted fake model** (programmed to emit exact tool-call sequences + text, with fault-injection knobs for delay/error/empty so the same harness also exercises failover and responsiveness) is the day-to-day integration backbone; **record/replay** fixtures are added once a feature works, to confirm our expectation of real LLM behavior isn't way off. To stop replay fixtures rotting silently, each fixture is stamped with `model` + a **hash of the system prompt + tool definitions** + `recordedAt`; replay runs offline per-commit and **auto-fails with "fixture stale — re-record" when the current prompt/tool hash differs**, which is the dev-time "don't forget" nudge. Re-recording (`test:record`, hits the real model) is **on-demand plus a nightly/daily safety net** that also runs the golden-path live eval — deliberately not per-PR keyed CI, to keep it simple.
