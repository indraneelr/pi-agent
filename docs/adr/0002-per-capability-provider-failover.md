# Per-capability providers with automatic timeout-failover

Gemini is the standard BYOK stack (model + Google Search grounding), but it periodically degrades to near-unusable slowness that is *not* rate-limit related, so we refuse a hard Gemini dependency. Each capability — **model**, **web search**, **image search** — is an independently configurable, ordered provider list `[primary, fallback]` with a **configurable per-call timeout**; exceeding the timeout (or erroring) auto-drops to the fallback mid-request, because a manual switch cannot rescue an in-flight session and only a timeout — not an error — catches slowness. Failover is **piecewise**: the model can stay on Gemini while search independently drops to SearXNG/Stagehand. v1 fallback targets are the free-but-slow options we already have (kimi via Ollama Cloud for the model, Stagehand for web search, SearXNG staying primary for images because it returns better results than stock APIs like Unsplash — but note the image *licensing* posture in ADR 0005 stages SearXNG down to an attributed fallback behind Wikimedia before public launch). We accept that these fallbacks are slow rather than fast — the consequence is that failover keeps the product *working*, not *fast*, which is why perceived-responsiveness (progress feedback) is handled separately and is the primary UX lever (see the responsiveness ADR).
